# 4.5.3 SystemUI TTML 缓存

这版主要解决一个使用上的问题：Bridge 的设置页不应该为了让 AMLL TTML 缓存生效而一直留在后台。

## 这次改了什么

- AMLL TTML 的读取、写入、自动清理和手动清空现在都在 SystemUI 进程中完成。
- 缓存文件写入 SystemUI 自己的 `cache/amll-ttml` 目录。播放歌曲时，SystemUI 直接读取本地 TTML；没有命中时照常请求 `api.amll.dev`，成功后写回 SystemUI 缓存。
- Bridge 设置页不再提供缓存 Provider，也不再需要作为缓存宿主常驻。关闭设置页或让 Thanox 回收 Bridge 进程，不会影响已经加载的缓存逻辑。
- 设置页的“AMLL 缓存自动清理上限”和“清理缓存”仍然保留。它们通过 Bridge 现有的签名权限广播通知 SystemUI，容量上限会在 SystemUI 重启后继续使用。
- 原有的在线歌词来源顺序、网易云歌曲 ID 直取、QQ 音乐和酷狗搜索、AMLL 优先选择以及失败回退逻辑保持不变。

## 对现有缓存的影响

升级后缓存位置从 Bridge 的应用缓存目录改为 SystemUI 的应用缓存目录，因此旧目录里的 TTML 不会自动搬运。第一次播放每首歌时可能重新请求一次 AMLL；之后由 SystemUI 自己管理缓存。缓存目录仍属于 Android 的 cache 目录，系统在存储空间紧张时可能清理文件，清理后会自动重新获取。

## 使用方式

1. 安装本版 Bridge，并在 LSPosed 中保持 `system` 与 `com.android.systemui` 作用域。
2. 重启 SystemUI 或重启设备，让新模块代码加载。
3. 在 Bridge 设置页调整来源顺序或缓存上限后即可关闭设置页；不需要把它挂在后台。
4. 如果需要清空 TTML，打开在线歌词设置页点击“清理缓存”。请求会交给当前 SystemUI 处理。
