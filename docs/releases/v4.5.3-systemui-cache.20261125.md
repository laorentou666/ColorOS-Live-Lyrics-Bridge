# 4.5.3 SystemUI TTML 缓存

本版把 AMLL TTML 缓存的宿主从 Bridge 应用迁移到 SystemUI。这样歌词请求、缓存读取和缓存写入都在实际使用歌词的 SystemUI 进程中完成，Bridge 设置页关闭、Bridge 进程被回收或被 Thanox 停止后，缓存仍可正常命中。

## 功能变化

- TTML 文件现在写入 SystemUI 的 `cache/amll-ttml` 目录，并按平台和歌曲 ID 的 SHA-256 键保存。
- 未命中缓存时仍请求 `api.amll.dev`，成功后直接写回 SystemUI 缓存；缓存达到上限时按最旧文件清理。
- 设置页不再提供缓存 ContentProvider，也不需要 Bridge 进程常驻。缓存上限和清空操作通过现有签名保护广播同步到 SystemUI。
- 在线歌词来源、网易云歌曲 ID 直取、网易云/QQ 音乐/酷狗与 AMLL 的并行获取和失败回退逻辑保持不变。
- 升级后旧 Bridge 缓存目录不会自动搬运；每首歌第一次播放可能重新请求一次 AMLL。SystemUI 的 Android cache 目录仍可能被系统清理，清理后会自动重新获取。

## 修复

修复了 SystemUI 并发处理歌曲元数据时可能重复初始化 TTML 缓存的问题。缓存实例现在只初始化一次，避免并发写入共用临时文件。
